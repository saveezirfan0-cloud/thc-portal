Role-based routing after sign-in

§1.4
Admin→ /dashboard (this Back Office). Full menu: events, onboarding, staff, compliance, clients, venues, roles, reports, feedback. Client→ /client (Client Portal). Only their own events + line-up, no rates, no totals. a client never sees the back office and vice versa Staff→ mobile app only. Activated through a personal link, sets their own password; no web login.
Behaviour notes. Login for back office and client is email + password (§1.4). One name + one logo everywhere: "The Hospitality Company" with the two-glasses logo in a cyan box — the circle is the only round element on the page (§1.6). Auth screens follow A0 Login · A1 Forgot password · A2 Reset link sent · A3 Set new password (§10.2). All auth mail is sent from admin@thehospitalitycompany.co.uk (§9.12). There is no sidebar here because nobody is signed in yet; after sign-in the Admin lands on the Dashboard (§9.1). Auth is DRF Token (§1.3); "keep me signed in" only lengthens the token lifetime on this device.
