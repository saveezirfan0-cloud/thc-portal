Behaviour notes. Order of entry: Client → venue (address → geo point, type → radius) → date/time → roles (§3.2). The overall start/end only pre-fills each role; every role section holds its own start and end, headcount, buffer (absolute, shown "6 (+1)"), charge rate from the client's rate card, pay rate, dress code (client's list for that role + "Other" free text for this event only) and auto-assign allocation (default headcount + buffer, editable; switch default ON, purple — §3.4). Hard validation per role: end must be at least 4 hours after start; after-midnight ends are allowed (§3.2). Time inputs are entered in UK time and say so in the label (§1.8). PO Number is manual, optional, free-format, editable any time (§3.2). On-site contact and notes are visible to staff in the app (§10.4). Break policy and Buffer policy are client-level toggles shown here read-only (§3.2). Editing is allowed only up to the event's start; changing a role's time / date / venue / dress code re-confirms that role's booked staff only (N11, §3.5); headcount below confirmed never auto-removes anyone. Duplicate copies roles, not staff. The derived event window (earliest start → latest end, RULE-18) drives status and the calendar.
