Status is computed from the event window: Upcoming before the earliest role start, Ongoing between, Completed after the latest role end; only Cancelled is set by hand (§1.5). A viewer outside the UK would see a second "your time" line under every window here (§1.8).
Behaviour notes. Two views, one toggle reading "List" first, "Calendar" second, working both ways with no duplicate (§3.1). Back / forward arrows around the period label in both views, so past events are browsable in List too. "+ New event" lives in the top-right of the header in every view. Cells and week columns scroll to hold 10–15 events a day; fill indication = EventChip full / N-open plus a daily "N ev · M open" counter (§3.1). Week view: seven Monday–Sunday columns, current day highlighted, chips ordered by event-window start, each chip showing start–end, client, venue and an "N of M" pill — amber while short, green when every role is confirmed; column headers carry the date and the same counter. Headcount reads "N (+buffer)" everywhere, never the total (§3.2, RULE-07); fill counts ONLY confirmed. The event window is derived from the earliest role start to the latest role end (RULE-18) — individual role times are on the row and on the event board. A cancelled event stays visible, greyed, with a Cancelled label; it contributes nothing to financials (§3.3). Status pill Upcoming / Ongoing / Completed / Cancelled per §1.5 appears on every row and chip. Duplicate copies the roles, not the staff (§3.2).
