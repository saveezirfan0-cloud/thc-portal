## Executive summary: NOT READY for the client review

The code is well organised and the automated checks are green. Lint, typecheck, 1,916 Vitest tests, 3 builds, 2,945 pgTAP assertions (only the known 2 failures), the format check and the three repo checks all pass. Most of the scope is implemented, and the money and personal-data isolation for clients and workers holds on the live database.

It is still not ready, for five reasons:

1. **The live deployment is split and the database deploy is red.**
   - The `deploy-database` job on `main` (826a2f6) failed: `supabase db push` refuses 14 migrations dated *before* the newest one already applied (#57 used 20260926… timestamps after #56's 20260927… had shipped).
   - 15 repo migrations are missing from live. Vercel is serving 826a2f6 app code against d59ae76's schema. For example, `/compliance` "confirm right-to-work date" calls `compliance_confirm_rtw_date`, which does not exist on live.
   - ADR-0026's client hardening is not live. Verified: Marco can read `events.auto_assign`, `pays_buffer`, `pays_breaks` and `notes` straight from the table.
   - The GDPR login ban is not live. The live `remove_worker` never touches `auth.users`.
   - The two branches' `booking_tick` / `release_unready_bookings` bodies now differ between a fresh reset and a pushed database.
2. **The core auto-assign loop is wrong in three ways that a demo would expose:**
   - (a) Hourly rounds stop once `confirmed + invited ≥ target`, so unanswered invitations stall the section. §3.4 says rounds keep adding.
   - (b) Check-in moves a booking to `worked`, but `shift_fill` counts only `confirmed`. A full section therefore reads as empty once people check in, and escalation invites more workers every 10 minutes, ignoring the target.
   - (c) "Booked elsewhere" and the Accept overlap check ignore a worker who is already checked in elsewhere.
3. **Two day-of-shift rules pay the wrong money:**
   - "Get back" on the event board records no arrival (the worker is paid £0), and `booking_tick` re-raises the No-show a minute later.
   - A "Left early" violation is never raised, so the 4-hour floor pays workers who leave early.
4. **Privacy defects:**
   - A worker can read the manager's rejection note on their own conviction declaration (verified live).
   - GDPR removal leaves the login email, `profiles.full_name`, the NI number in outbox payloads, the location trail, visa data and more.
   - No office action passes `p_actor`, so every remove, block, unblock and reset audit row has a null actor.
5. **Nothing background has ever run live.**
   - 0 cron jobs, 0 Edge Functions, 0 `job_runs` and 0 outbox rows. `settings.edge_base_url` is unset and there is no vault `service_role_key`.
   - So no auto-assign, 12:05 cutoff, reminders, No-show or No check-out detection, or sends. Much of what the client would be shown as "automatic" cannot happen on the live project.

Several PR #56 claims do not hold as stated:
- **Claim 4** (the shared redirect guard is used everywhere): #57 added a second office reset flow with its own guard, and `/..//evil.com` escapes it. Reproduced.
- **Claim 7** (N6/N7): built, but not scheduled live.
- **Claim 11** (forgot password): depends on unset environment variables and PKCE same-browser behaviour.
- **Claim 12** (office screens): Verify/Reject exists for declarations, not documents.
